# 会话里的画面

去连别人的会话窗口，侧边面板的"设置"里选画面。都是去连的一方向被连的一方提的要求（SDK 的 `rcs_view_request_config`），
运行中换、不用重连；记在偏好设置里，连哪台都用。对方的画面是连着它的所有人共用的，听先连上的那个人的（主观看端）。

- **分辨率、帧率、码率**：不超过对方显示器的原始分辨率、刷新率；码率"自动"时按分辨率和帧率算（`App/src/session/view_quality.h`）
- **编码器**：HEVC、H.264、AV1、VP9 里两边都用显卡编解得了的才列（对方经控制通道说它用显卡编得了哪几种，
  `encoders`）；一个都没有时才列要用 CPU 的。自动：两边都用显卡的 HEVC 首选，没有时 H.264，只能用 CPU 时 H.264。不带 SDK 的 CPU 编码库：VP9 只有 Intel 显卡编得了（要被采集的显示器
  接在它上面），Mac、NVIDIA 都不编
- **文字更清楚**（4:4:4）：颜色精细到每个像素，看代码、表格时字边不糊，码率高一些。两边都把 4:4:4 加进画面格式
  （被连的一方 4:2:0 排第一，默认不变），去连的一方要时指定。只用两边都用显卡做得了的编码格式：对方提供的
  （`rcs_peer_info.codec_limits[].picture_formats`）和本机显卡解得了的（`rcs_list_codec_implementations`）；
  Mac 上一般是 HEVC，Windows 上要 NVIDIA（NVENC / NVDEC）或 Intel（oneVPL）的显卡。都做不了时不显示这个开关。
  解出来的画面 Mac 上是两个平面（和 4:2:0 一样画）、Windows 上是 BGRA 纹理，渲染不用改
- **低延迟模式**：两边都换成 SDK 的低延迟预设（`RCS_PRESET_LOW_LATENCY`）：被连的一方操作以后加速采集、每帧发得更快、
  起始码率更高，去连的一方解码队列、声音缓冲更短。适合在同一个网络里操作。去连的一方连上时、改了时经控制通道告诉对方
  （`lowLatency`），对方听主观看端的，主观看端走了就按下一个人的
- **显示器的缩略图**：工具栏上的显示器图标点开，每一块一张缩略图，点哪块看哪块。打开时向对方要（`thumbnails`），
  对方用 SDK 的缩略图模块在采集的那台机器上截（装好的 macOS、Windows 上在助手那里），在另一个线程上一块一块截，
  像素压缩后经控制通道发回来（`thumbnail`）

## 键盘

- 按键按它在键盘上的位置发过去（USB 键码，`App/src/remote_view/remote_input.h`），打出什么由对方的键盘布局决定。
  Mac 连别的电脑时 Command 当 Ctrl 用、Control 当 Win 键用，Command+C 在那边也是复制
- Windows 上控制对方、画面有焦点时，Win 键由比邻截下来发给对方（`system_keys_win.h`）：Win+V 到了 Mac 上是
  Command+V，本机不弹剪贴板。Win+L、Ctrl+Alt+Del 系统不让截；Ctrl+Alt+Del 在"发送快捷键"菜单里
- 不是 Mac 的电脑连 Mac：F1~F12 当 MacBook 键盘顶上那一排用——亮度、调度中心、聚焦搜索、上一首、播放、下一首、
  静音、音量（F5、F6 照旧是 F 键）。按着修饰键时还是 F 键，像在 Mac 上按着 Fn
- 正连着本机的那台电脑，不能再反过来去连它（两边的画面互相套着，越套越卡）
