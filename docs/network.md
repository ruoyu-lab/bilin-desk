# 网络：怎么连、什么时候走中继

## 怎么连

- **信令**（两台机器交换"我在哪、怎么找到我"，SDK 给的一段文字）：经服务器的长连接，或者在局域网里直接连对方的信令端口（附近的设备、按 IP 地址连，不经服务器）
- **连接**（画面、声音、键鼠）：SDK 的连接，端到端加密，服务器和中继只看得到密文。两种传输方式：
  - **直连**（P2P）：SDK 用 ICE 找一条两端都能通的路。覆盖局域网、IPv6、多数家庭宽带和手机网络。STUN 告诉每一端它的公网地址
  - **中继**（TURN）：两端都连到中继服务器，由它转发。只要两端都连得到中继就能通，但多走一段路、占服务器的带宽
- SDK 要求两端用同一种传输方式，一次运行里不变；直连打不通不会自己改走中继，由程序两端都换成中继重来。分享端一次运行只能是一种，服务所有来连的人
- 两端的网络协议得一样：SDK 握手时自己核对，不一样时观看端的会话以"不支持"结束（说明里有 protocol version），
  提示两边都更新到最新版本。程序 0.1.1-beta 和以前的还按信令里的 SDK 版本（`sdk`）自己比对，不一样就回绝 `version`，
  没带这个字段的信令不收：所以信令照旧带着它，这些版本都更新掉以后删

## 连着的时候换了网络

换 Wi-Fi、插拔网线、开关 VPN 时连接不断：SDK 换一条路接着用，同样的密钥、控制权、在传的文件。直连、中继要重新打洞时，SDK 会在连接中途再发信令，所以信令的路一直留着：

- 界面里去连别人的连接：后台服务一直记着它的信令往哪送，直到界面说这次连接结束（`endSignal`），或者界面程序断开
- 来连本机、连上了的：本机的回答从它来的那条路回去，直到那个人走了；SDK 认的路由号也一直留着。没连上的两分钟没动静就忘掉
- 局域网里的信令 TCP 连接跟着这次连接，结束时才关
- 网线、WiFi 都连着的电脑：画面、声音走哪块网卡由 SDK 的 ICE 定，系统默认走的那块网卡（一般是网线）优先。
  局域网发现里每块网卡的地址都听得到它，广播里带着它默认网卡的地址（`address`），附近的设备、局域网信令连那个；
  没带的（旧版本）一直用正在用的地址，听不到了才换，不在几个地址之间来回跳（`Service/src/lan_discovery.h`）
- 路断了一阵（对方那边还没找到新路）：观看端显示"重连中"，分享端给它留 30 秒；路回来了控制权照旧（`restore_control`）。30 秒内没回来就和以前一样，观看端重新连上、直接让进

## P2P 和中继用的服务器

服务器上的 coturn 同时是 STUN 和 TURN。

- 设备登录服务器时（`welcome`）发来：STUN 的地址、TURN 的地址和到它怎么走（UDP 或 TCP）、有时效的凭据。凭据是 coturn 的 REST 凭据：`username = 过期时间（秒）:设备 ID`，`password = base64(HMAC-SHA1(共享密钥, username))`，coturn 用同一个共享密钥验证，服务器不用记发出去的凭据。默认一天有效，过了一半服务器再发一份新的（`ice`）
- 后台服务收下（`ServerLink`）：分享会话用它，凭据换了从下一个连接起用；经 `ice` 主题交给界面里去连别人的会话。和服务器断着、凭据到了期，中继就不能用了，直到连上服务器拿到新的
- 中继的地址：没设 `TURN_HOST` 时跟着设备连服务器用的主机名（Nginx 转来的 Host 头）。开发时 coturn 和服务器在同一台虚拟机上，Mac 连的是 `localhost`、局域网里的 Windows 连的是 Mac 的地址 `192.168.55.173`，中继也就分别是 `localhost:3478`、`192.168.55.173:3478`，不用按设备另配。正式部署时中继和服务器是同一个域名也不用设，不是时设 `TURN_HOST`

服务端的环境变量（`Server/ecosystem.config.cjs`）：

| 变量 | 意思 | 默认 |
| --- | --- | --- |
| `TURN_SECRET_FILE` | 共享密钥所在的文件（只在服务器上，不进仓库）。没设就不发 ICE 配置，设备只能直连，也没有 STUN | 没设 |
| `TURN_HOST` | 设备连中继用的主机名 | 跟着 Host 头 |
| `TURN_PORT` | 中继的端口 | 3478 |
| `TURN_TRANSPORT` | 设备到中继走 `udp` 还是 `tcp`（只放行 TCP 的网络） | `udp` |
| `TURN_TTL_S` | 凭据的时效（60 秒到七天） | 86400（一天） |

## 什么时候走中继

信令里带着这次连接的传输方式（`p2p` 或 `relay`，`rc/transport.h`），服务器、局域网、界面和后台服务之间的信令都带。

**观看端**（界面程序的 `ViewerSession`，`rcconnect` 一样）：

1. 先直连，带服务器给的 STUN。有中继可以改走时，连通检查只等 5 秒（SDK 默认 15 秒），早点知道直连不通
2. 直连打不通（`RCS_ERROR_NETWORK`，还没连通过）、有中继：换一个连接编号，经中继再连一次
3. 被回绝 `transportBusy`：
   - 自己是直连的：对方正经中继服务别人。有中继就直接经中继再连
   - 自己是经中继的：对方正被别人直连着，换不了。提示"对方正被别人连着，暂时没法走中继，稍后再试"
4. 被回绝 `noRelay`（对方没连上服务器，没有中继）：提示连不上
5. 没有中继（本机没连上服务器、服务器没配）：直连打不通就照原来的提示

**分享端**（后台服务的 `ShareHost`，什么时候换由 `ShareTransport` 定）：

- 来的信令和现在的传输方式一样：照常
- 不一样、本机没人在用：换成对方要的，重开分享会话，再处理这份信令
- 不一样、有人在用：回绝 `transportBusy`。"在用"：有人连着、在等本机的人点允许、路断了在等它回来（一分钟），或者别的设备刚来连过还没连通（25 秒内：重开会断掉它）。同一台设备直连打不通改走中继不算
- 要中继、本机没有中继：回绝 `noRelay`
- 经中继时人都走了（SDK 回到没有连接的状态，回绝的话已经送到）：换回直连
- 经中继时分享会话停了（中继连不上、凭据被拒）：换回直连接着接受连接
- 关掉"允许别人连接本机"、出错后再试一次：从直连开始

## 正式的服务器

bilindesk.com（Rocky Linux 9，不到 1 GB 内存，在首尔）：

- 程序连 `wss://www.bilindesk.com/ws`（Nginx，443 端口）。证书是 Let's Encrypt 的，程序按系统信任的证书机构校验；
  换服务器时把域名指过去就行，不用发新版程序
- 域名的解析不能经 CDN 代理（Cloudflare 的"仅 DNS"）：中继跟着设备连服务器用的主机名，要直接连到这台服务器
- coturn：3478（UDP、TCP），中继端口 49152–49407（UDP）。服务器在 NAT 后面：中继地址用内网地址，
  告诉设备公网地址（external-ip）；两个中继分配之间经公网地址转发是通的
- 装：`Server/deploy/setup-production.sh`；部署：`Server/deploy/deploy-production.sh`（服务器上放了什么见 [admin.md](admin.md)）。
  防火墙只加这几个端口，服务器上原有的东西不动
- 云服务商控制台里的防火墙也要放行：TCP 80、443，TCP 和 UDP 3478，UDP 49152–49407
- 安装包连正式的服务器（`-DRC_SERVER_URL=wss://www.bilindesk.com/ws`），开发版（build 目录里直接运行的）连 Mac 上的虚拟机

## 开发环境的 coturn

`Server/deploy/setup-dev.sh` 在虚拟机 bilin-dev 上装 coturn 和 coturn-utils（EPEL），能重复执行：

- 共享密钥 `/etc/bilin/turn-secret`：第一次生成（`openssl rand`），之后不变，只有当前用户能读；服务端经 `TURN_SECRET_FILE` 读它，coturn 的配置里也写着它
- `/etc/coturn/turnserver.conf` 每次按虚拟机现在的地址重写：听 `0.0.0.0` 和 `::` 的 3478（UDP、TCP），没有 TLS；中继地址（`relay-ip`）是虚拟机自己的地址，中继端口 49152–49407；`use-auth-secret`；只在中继地址之间转发（别的地址都拒绝，不能被拿来当跳板）
- 虚拟机重建、地址变了，重跑一遍

OrbStack 的端口转发（实测）：

- 虚拟机里听在 `0.0.0.0` / `::` 的端口，OrbStack 在 Mac 的所有地址上转发，UDP 和 TCP 都转；只听具体地址（127.0.0.1、虚拟机的地址）时只转到 Mac 的 localhost，局域网里的电脑连不到。所以 coturn 要听 `0.0.0.0` 和 `::`
- IPv4、IPv6 跟着虚拟机里听的：Mac 上 `localhost` 先解析成 `::1`，coturn 也听 `::` 才转得过来
- UDP 转得过来，开发环境中继走 UDP；要试只放行 TCP 的情况设 `TURN_TRANSPORT=tcp`
- 转进来的包在虚拟机里看到的来源是 127.0.0.1：开发环境里 STUN 查到的"公网地址"没有意义（直连照样用本机网卡的地址），中继不受影响

## 怎么测

**coturn 本身**（在虚拟机里，`orb -m bilin-dev bash`）：用和服务端一样的算法签一份凭据，`turnutils_uclient` 开两个分配互相转发：

```sh
secret=$(cat /etc/bilin/turn-secret)
user="$(( $(date +%s) + 600 )):900000099"
pass=$(printf '%s' "$user" | openssl dgst -sha1 -hmac "$secret" -binary | base64)
turnutils_uclient -y -n 20 -m 1 -u "$user" -w "$pass" 127.0.0.1      # UDP：发的和收的一样多
turnutils_uclient -t -y -n 20 -m 1 -u "$user" -w "$pass" 127.0.0.1   # TCP
```

过期的凭据分配不了（`Cannot complete Allocation`），转发到别的地址（`-e 8.8.8.8 -r 53`）被拒（403）。

**两台电脑经中继连**：用 `rcconnect`（`tools/rcconnect`，界面程序里没有"总是走中继"的开关）。被连的电脑照常开着程序：

```sh
build/debug/tools/rcconnect/rcconnect --relay 设备ID 临时密码   # 一开始就经中继
build/debug/tools/rcconnect/rcconnect 设备ID 临时密码           # 先直连，打不通再经中继（和界面程序一样）
```

- 连的一方打印"经中继 localhost:3478（UDP）"，连上时"已连上，经 relay … on TURN …"（SDK 选的路）
- 被连的一方的 `service.log`：`设备 … 要经中继连本机，换过去`、`开始接受别人连接本机（经中继）`，人走了以后 `经中继连本机的人都走了，换回直连`
- 被连的一方正被别人直连着时 `--relay` 会被回绝：`对方回绝了：transportBusy`
- Windows 上的 rcconnect 连 Mac 的地址：编译时 `-DRC_SERVER_URL=ws://<Mac 的局域网地址>:8800/ws`
