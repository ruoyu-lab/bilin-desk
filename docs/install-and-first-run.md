# 安装与第一次打开

目标：用户不用知道"无人值守"这回事。装好、按引导点完授权，自己的设备就随时能连这台电脑。

## 连接规则

按"谁在连"定死，不给开关：

| | 自己的设备 | 别人 |
|---|---|---|
| 怎么连 | 直接连，不用密码 | 临时密码（每次用完就换） |
| 要不要有人点允许 | 不用 | 必须有人在电脑前点允许 |
| 锁屏、没登录、刚开机 | 能连（开着"开机时自动启动"时） | 连不上 |

自己的设备要随时能连，后台服务就得开机就运行、没人登录时也在。装这样的服务要管理员确认：这一下放进安装，不留到以后让用户另点。

"允许别人连接本机"关掉时别人连不上，自己的设备不受影响。

## 开机时自动启动

服务总是在安装时装好；设置里的"开机时自动启动"决定登录时界面程序自己打开不打开，和界面程序没开着时我的设备还能不能连。

- 默认开：主要的用法是在外面连自己家里、公司的电脑，关着的话要等用的时候才发现连不上，那时已经没法补救。开着时开机不弹任何窗口，只有托盘 / 菜单栏里一个图标
- 只在需要时用的人（比如偶尔让别人帮忙看看）可以关掉：之后只有打开程序时才能被连接
- 托盘里的"退出"就是退出：本机不再能被连接，直到再次打开程序，或者下次开机（开着自动启动时）。
  装了系统服务、开着自动启动时例外：我的设备照样能连（见上面的"现在的做法"）
- 有人连着本机时界面程序一定在（本机的人要看得到谁在连、收得到消息、能断开对方）：
  - 托盘的"退出"、macOS 的 Cmd+Q 先问一句"退出会断开正连着本机的人"，确认了断开再退出；注销、关机不拦
  - 界面程序意外没了（崩溃、被结束）：后台服务把它拉起来，只在托盘、刘海里，不弹窗口（`--background`）；
    15 秒内没连上后台服务就断开连着的人

### 现在的做法

后台服务有两种运行方式（rc/system_service.h、Service/main.cpp）：

- **装好的**（Windows 的安装程序、macOS 的 .pkg）：后台服务是系统里的服务，开机就运行，没人登录、锁屏时也在。
  - Windows：LocalSystem 服务 `Bilin`（`--system-service`），里面是 SDK 的看护者，在控制台会话里以 SYSTEM 启动后台服务
    （`--helper`），跟着锁屏、登录界面、UAC 的安全桌面，能发 Ctrl+Alt+Del（安装时打开 `SoftwareSASGeneration` 策略，卸载时改回去）。
    注销、换用户时看护者重启它，连着的人自己重连
  - macOS：LaunchDaemon（root，`--daemon`）运行后台服务，持有连接；LaunchAgent 在登录窗口和每个登录用户的会话里运行助手
    （`BilinAgent`），录屏、声音、键鼠、读写文件在助手里（SDK 的 agent 链接），授权是助手的。后台服务只认控制台前的那个用户的助手
  - 整台电脑一份身份、设置、日志（`rc::system_service::stateDirectory()`），只有 SYSTEM / root 和管理员能读写；程序和它所在的目录
    只有管理员能改，不然后台服务不以 SYSTEM / root 运行。每个用户的界面程序都连它，只认控制台前的用户和管理员（`client_rights`）
  - 设置里的"开机时自动启动"同时管两件事：用户登录时界面程序自己打开（系统的登录项），和界面程序没开着时后台服务还接不接受我的设备连接
    （`unattended`）。关着就像没有系统服务：只有打开程序时才能被连接，托盘里的"退出"就是退出。开着时"退出"只退出界面程序
    （断开正连着的人），我的设备照样能连
  - 没人在电脑前时（登录界面上没人登录），连着的只会是我的设备，用不着界面程序
- **开发时编出来的**（没装）：后台服务以当前用户运行，由界面程序启动，只有这个用户的界面能连它，跟着界面程序退出。

静默安装、卸载（给管理员批量部署）：`Bilin-Setup.exe --quiet`，不要界面，做完就退出，没成时退出码 1。

- 用系统的登录项：macOS 是 SMAppService.mainApp（"系统设置 → 通用 → 登录项"里看得到）；Windows 是当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值是带引号的程序完整路径加 `--autostart`
- 设置里的开关就是系统里的状态，不另记一份：在系统设置里改了，回到程序时跟着变。系统设置里没允许时（macOS 的"登录项"里要用户允许、或者被关掉了；Windows 在任务管理器或设置的"启动"里被关掉了），设置页说明，给按钮打开系统设置的那一页
- 第一次运行时替用户打开，在偏好设置里记一笔（`autostartDefaultApplied`），只这一次：之后用户关了、系统没让开，都不再自动去开
- 登录时由系统启动的不弹窗口。macOS 上 SMAppService 启动程序不带参数，看系统发来的"打开程序"事件（Apple Event）：登录项启动的带着 `keyAELaunchedAsLogInItem`，这个事件在 AppKit 发"启动完了"的通知时读得到。Windows 上看命令行里有没有 `--autostart`
- 开发时：登录项指向打开它时运行的那一份，比如 `build/debug/App/Bilin.app`、Windows 上 `build-windows.cmd` 的安装目录。Windows 上换了位置运行，开关显示关着，打开就换成这一份；macOS 上换了位置要在设置里关掉再打开。构建目录删掉以后登录时就什么都不启动

## Windows：安装时一次装好

- 安装程序本来就要管理员确认（一次 UAC 弹窗）。确认以后一起装好：
  - 程序
  - 后台服务：没人登录、锁屏、UAC 弹窗时也能被自己的设备连上；开机时运行不运行按"开机时自动启动"
  - 防火墙放行：第一次被连接时不再弹"Windows 安全中心警报"
  - 允许服务模拟 Ctrl+Alt+Del（远程解锁、登录要用）
- 装完直接能用：没有第一次打开的引导，之后也不会再出现"安装服务""允许访问网络"之类的弹窗
- 升级：新的安装程序直接覆盖，服务自己停下、换掉、再启动，用户什么都不用做
- 卸载：安装时改过的全部还原——服务、文件、防火墙规则、Ctrl+Alt+Del 策略、程序的数据

### 安装包

不用现成安装工具的向导界面（样式太老），安装界面自己用 Qt Quick 做，和程序一个样子：

- `Bilin-Setup.exe` = 自己写的解压程序（tools/setup/stub.cpp）+ 压缩好的程序文件（tools/setup/archive.h 的格式，
  Windows 自带的 LZMS 压缩）。双击后弹一次 UAC（清单里要管理员），静默解压到临时目录，以安装模式启动程序
  （`Bilin.exe --setup install`），装完删掉临时目录
- 安装界面只有一页（App/qml/setup/SetupWindow.qml）：程序图标和名字、"立即安装"、下面一行小字"安装到 …  更改"；装的时候按钮换成进度条，装完换成"打开比邻"。装到一半不能关
- 卸载、升级用同一个界面："应用和功能"里点卸载，程序把自己复制到临时目录再以管理员身份打开卸载界面（装着的那份要被删掉）
- 原来由安装工具做的事自己做（App/src/setup/）：停掉正在运行的程序、复制文件（先放到 `.new`，再和旧的换）、登记到"应用和功能"、
  开始菜单快捷方式、防火墙放行；一步失败就倒着还原已经做了的；卸载时全部还原，程序的数据（`%APPDATA%`、注册表、开机启动）一起删掉
- 没有管理员权限的账户不让装（要 UAC 确认）
- VC 运行库的 DLL 跟着程序放（从 VS 开发环境的 VCToolsRedistDir 拿），没装过 VC 运行库的电脑上也打得开；
  通用 C 运行库（UCRT）Windows 10 起自带。安装程序本身静态链接 C 运行库
- 做安装包：`scripts\build-windows-installer.cmd <Qt 目录> <构建目录> <输出目录>`，连正式的服务器；在 Mac 上用 Parallels 里的 Windows 编：`scripts/build-windows-vm.sh`。
  打包程序写完以后用安装程序解压的同一段代码读回来，和程序目录里的逐个文件核对

## macOS：安装时装好服务，第一次打开时引导授权

### 安装

用 .pkg 安装包：安装时输一次管理员密码，程序和后台服务一起装好。

- `scripts/build-macos-pkg.sh` 做 `Bilin.pkg`：连正式的服务器，装到 `/Applications/Bilin.app`
  （固定位置，不让安装器去"升级"构建目录里同一个标识的开发版本）
- 安装前（App/platform/macos/pkg/preinstall）停掉正在运行的程序和后台服务

拖进"应用程序"的 .app 装不了开机就运行的服务，之后还得再要一次密码，或者让用户去系统设置里批准，多一步。

### 第一次打开：授权引导

"屏幕录制"和"辅助功能"只有用户自己能在系统设置里打开，程序替他开不了，所以第一次打开时带他点完。

- 什么时候：装好后第一次打开，在主窗口之前（授权是这台电脑的事，不登录也要）。登录时由系统启动的不弹
- 一页，两行，每行一句大白话和一个按钮（App/qml/setup/PermissionWindow.qml）：
  - 屏幕与系统音频录制：让你的其他设备看到、听到这台 Mac
  - 辅助功能：让你的其他设备操作这台 Mac
- 点"去打开"：后台服务弹出系统的授权提示（只有第一次会弹），同时跳到系统设置里对应的那一页；授权一打开，
  程序里那一行就显示勾。装好的程序里授权是助手的：助手缺授权时每 3 秒另启动一个自己去看，变了就退出、由 launchd
  再启动，后台服务从重新连上来的助手那里拿到新的授权（屏幕录制、辅助功能系统都给每个进程只查一次，助手不重新启动
  就一直以为没有；系统让"退出并重新打开"的是界面程序，不是助手）
- 两个都打开后点"完成"进入程序；也可以"以后再说"。早就都授权过的（比如开发时）不显示，直接进入程序
- 系统要求重新打开程序时（打开录制权限后常见）：重新打开后回到引导页，打开了的那一行已经打勾。没走完就关掉窗口的，
  这次进入程序，下次打开还有
- 走完以后不再出现（偏好设置里的 `permissionGuideDone`）。授权以后被关掉了，由概览页顶上的提示条带用户去打开

### 升级、卸载

- 升级：新的安装包直接覆盖，服务自己重启。授权跟着程序的签名走，签名不变就不用重新授权
- 卸载：服务、文件、程序的数据都删掉。macOS 没有系统的卸载入口，放在程序的"设置 › 关于比邻"最下面（"卸载比邻"，只在装在"应用程序"里时有）；删程序要输一次管理员密码

## 签名

能不花钱就不花钱：

- Windows：开源项目可以申请 SignPath 基金会的免费代码签名（要审核，构建放在它支持的 CI 上）。没签名时，用户第一次运行会看到"Windows 已保护你的电脑"，要点"更多信息 → 仍要运行"，每个新版本都会再出现
- macOS：不交年费就没法公证，用户第一次打开要去"系统设置 › 隐私与安全性"点"仍要打开"。用固定标识的临时签名，升级后录屏、辅助功能的授权不会丢
