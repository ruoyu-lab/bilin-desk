# 设备和账号

## 设备（已做）

- 设备 ID：9 位数字，本机随机生成，再到服务器登记；已经属于别的设备时服务器拒绝，本机换一个再登记。没网、连不上服务器时也有 ID
- 设备令牌：本机随机生成，证明"这个 ID 是我的"，服务器只存它的哈希。不登录账号也能登记
- 同一个设备 ID 只保留最新登录的一条连接
- 临时密码不上传服务器：它只在两台机器之间验证（SDK 的 PIN，端到端）
- 设备密钥：本机第一次运行时生成（SDK 的 generateDeviceKey），一直不变；公钥随登记交给服务器，以后"我的设备"、信任的设备不用密码时靠它认出是哪台
- 设备令牌和设备私钥存在本机的 identity.json 里：Windows 用 DPAPI 加密（只有这台电脑上的这个用户解得开，文件被备份、拷走也没用）；macOS 原样存在只有本人能读的 ~/Library 里（钥匙串要付费的开发者签名，临时签名的程序每次升级以后读钥匙串都会弹窗要钥匙串密码）。解不开时换新的令牌和密钥，服务器那边按新设备登记

## 账号（已做：注册、登录、退出、我的设备、改昵称、改密码、注销）

- 邮箱 + 密码注册，邮箱不分大小写；注册要先过邮箱验证码（下面）。服务器只存密码的 scrypt 哈希
- 登录 = 把本机挂到这个账号下：设备令牌认的是设备，账号只是设备的归属，退出就是解开。服务器记着本机挂在哪个账号下，后台服务重启、断线重连都不用重新登录
- 一个账号可以同时登录多台设备，它们互为"我的设备"
- 一台设备同一时间只登录一个账号；换账号要先退出再登录。不会出现同一个账号在一台设备上登录两份
- 账号只是把设备挂到账号下，设备 ID 不变；不登录也照样能用
- 在不在线：每台设备连着服务器就每 30 秒续一次（Redis，90 秒过期），账号下的设备变了、上下线了，服务器推给同一个账号的每台设备
- 移除我的设备：让那台设备退出这个账号（只能移除同一个账号下的）
- 设置 › 账号：改昵称；改密码要旧密码；注销账号要密码，账号删掉，挂在下面的设备都不再属于任何账号
- 忘记密码：登录窗口里点"忘记密码？"，邮箱收验证码，凭它设新密码，设好直接登录（也会认出重装过的电脑）

### 邮箱验证码（已做）

- 注册、找回密码都分两步：先填表，服务器往邮箱发 6 位验证码，再输验证码（登录窗口，`App/qml/auth/LoginWindow.qml`）
- 验证码 10 分钟有效；用对一次就作废，错 5 次也作废；再要一个就换掉之前的。存在 Redis，只存哈希（`Server/src/codes.ts`）
- 注册时邮箱不能已经注册过，找回密码时要注册过：发之前就说（`emailTaken`、`noAccount`），不白发邮件
- 限速：同一个邮箱一分钟一个、一小时 5 个；同一个地址一小时 10 个；服务器一天最多发 90 封（Resend 免费额度一天 100 封），
  到了说"今天发出的验证码太多了"（`mailLimit`）。界面上发出以后 60 秒才能重新发
- 邮件经 Resend 的接口发（`Server/src/mail.ts`），发件人 `比邻 <noreply@bilindesk.com>`；怎么配见 [admin.md](admin.md) 的"邮件"。
  开发用的虚拟机不真的发，验证码写进服务端的日志（`orb -m bilin-dev pm2 logs bilin-server`）
- 设备 180 天没上线，服务器上它的记录自动删掉（MongoDB 的 TTL 索引；连着的设备每 6 小时记一次还在用）

### 我的设备之间不要密码（已做）

- 一次分享只认一种身份（SDK）：后台服务开两个分享会话，**别人的**用临时密码（SDK 的 PIN）、要本机的人点允许，
  **我的设备的**只靠设备密钥（SDK 的 RCS_SECRET_NONE 加信任列表），不要密码、不用点允许，没有界面开着也照样让进
- 我的设备那个会话信任账号下别的设备的公钥（服务器发来的账号设备列表），本机去连它们时也只认它们的公钥；
  服务器只经手公钥，冒充不了任何一台。账号下没有别的设备时它不运行。不管"允许别人连接本机"开没开
- 信令带着这次怎么证明自己（`access`：password | device，rc/transport.h），被连的一方按它交给对应的会话，
  两边不用各自猜（按 IP 连自己的设备时，去连的一方不知道对方是谁，就按临时密码连）
- 对方不认这台设备（没登录同一个账号，回绝 notMine；或者握手时被拒）：改问临时密码。对方后台服务刚启动、
  服务器还没告诉它账号时回绝 notReady（不是说不认），没在等它重启、注销回来时也改问临时密码，说清是它还没连上服务器
- 编号：两个会话各有各的，给界面的合成一个（Service/src/share_ids.h）
- 还没做："信任这台设备"（别人的设备，手动信任以后不要密码）；没连上服务器时不知道账号下有哪些设备，
  这时我的设备也要临时密码

## 谁能看到在线、谁要密码

| | 我的设备（同一个账号，或者手动信任过的） | 别人的设备 |
|---|---|---|
| 能不能看到在不在线 | 能 | 不能 |
| 连接要不要密码 | 不要（也不用点允许） | 要临时密码，被连的人点允许（"信任这台设备"还没做） |

- 服务器不提供"某个 ID 在不在线"的查询；只在发起连接失败时告诉对方"连不上"，界面上说"对方可能不在线或 ID 不对"，不区分不存在和不在线

## 限速

免得有人挨个试设备 ID 和密码。计数在 Redis 里，几个实例共用，换一条连接、换一个身份也照样算（Server/src/hub.ts 的 Limits）：

| 什么 | 上限 | 超过以后 |
|---|---|---|
| 同一台设备、同一个地址 10 分钟里发起的连接 | 30 次、100 次 | 先不让连，界面上说"连得太频繁了，过几分钟再试" |
| 其中连不上的（对方不在线、没有这个 ID） | 10 次、30 次 | 同上 |
| 同一个地址、同一个账号 10 分钟里输错的密码（登录、改密码、注销） | 各 10 次 | 先不让试，"试错太多次了" |
| 同一个地址一小时里登记的新设备 | 20 台 | 不让登记，过一会儿再来 |

同一次连接重连时的信令不算新的一次。设备的地址是 Nginx 转来的真实地址（X-Forwarded-For 里 Nginx 加的那一个）

## 一台电脑一个身份（已做）

装好的程序里后台服务是整台电脑的系统服务，身份存在系统目录里：一台电脑只有一个设备 ID，不管有几个系统用户。
开发时编出来的后台服务按系统用户运行，身份在用户自己的目录里。

### 重装以后接回原来的 ID（已做）

卸载会删掉本机的身份（令牌、密钥、设备 ID），重装以后是一台新设备。登录同一个账号时服务器认出是原来那台电脑，
把原来的设备 ID 接回来：账号下不多出一台用不上的旧设备，别人记着的那个 ID 也照样能连。

- 认电脑靠硬件编号（macOS 的 IOPlatformUUID、Windows 的 MachineGuid）加上本程序的前缀以后的 sha256（rc/machine.h），
  随登记交给服务器；不发编号本身。重装系统以后会变，那时就是新设备
- 只在登录账号、密码对了的时候认（Server/src/hub.ts 的 signIn）：账号下有同一个硬件编号、同一个系统、现在不在线的设备时，
  那个 ID 换成这台设备的令牌和公钥，这台设备的新 ID 删掉；服务器发 renumbered，本机换回原来的 ID、用同一个令牌重新登录。
  账号下别的设备随即拿到它的新公钥（我的设备免密码照样能用）
- 原来的那个在线时不认：同一台电脑上同时开着两份（比如开发时编出来的和装好的）是两台设备
- 光凭硬件编号接不走 ID：要知道账号的密码

## 我的设备之间远程重启、关机（已做）

去连自己的另一台电脑时，会话窗口右上角的电源菜单里除了"断开连接"，还能让它重启、关机、睡眠、注销（SDK 的电源模块）。

- 不用打开什么：我的设备之间都能用（自己的电脑自己说了算），正在控制它的那一台才能要。
  别人的电脑一律没有，菜单里也不显示。对方的系统做不到的那一样不显示（比如现代待机的 Windows 笔记本不能睡眠）
- 只在自己的设备之间、去连的一方点之前还要确认，所以不倒数：确认以后交给 SDK，对方答应 1 秒以后就做
- 能不强制就不强制（程序会问要不要保存，在画面上就能处理）；对方做不了不强制的再强制一次：
  Windows 上以系统身份运行的后台服务注销用户，Mac 停在登录界面时重启、关机
- 重启、注销以后不等 SDK 自己重连（它只等 30 秒）：等账号里对方再上线就马上连，重启最多等 5 分钟、注销 2 分钟；
  对方还没下线、或者刚回来连不上时隔 5 秒再试（服务器限着连不上的次数，不在线时不试）。关机、睡眠以后停下来说明。
  对方答应以后连接不管怎么断（SDK 可能先自己换路重连，信令落到对方刚起来的后台服务上被回绝）都按这一样办
- 被控的一方的连接记录（通知）里记一笔"××远程重启了本机"
- Mac 开着文件保险箱（FileVault）时，重启以后停在开机解锁界面，要有人输入密码才能再连上

## 网络唤醒（已做）

我的设备睡眠、关机以后，从另一台叫醒它（SDK 电源模块的 Wake-on-LAN）：

- 连着我的设备时，它告诉去连的一方自己能唤醒的网卡（MAC 地址、IPv4 地址和网段，`share_wake_info`）。MAC 地址认得出是哪台电脑：
  只告诉我的设备，别人连进来时不说。去连的一方记在本机（状态目录的 `wake.json`，App 的 `DeviceWake`），它不在线时也用得上
- 唤醒包要从它所在的网段里发（UDP 广播到它网段的广播地址，隔一秒一个，共三个）。现在只从本机发：本机和它在同一个网段时才叫得醒；
  不在时说"本机和它不在同一个网络里"。经账号下另一台在那个网络里的设备代发还没做
- 会话窗口里对方已睡眠、已关机时有"唤醒"按钮，按了以后等它上线就自动连（最多 3 分钟，和重启以后一样等账号里它再上线）；
  主窗口里不在线的我的设备的详情页也有"唤醒"，下面写着叫不叫得醒、为什么
- 它的系统说没开网络唤醒（Windows 设备管理器里网卡的"允许此设备唤醒计算机"，macOS 的"唤醒以供网络访问"）时不发；
  主板、网卡固件里的设置（从关机唤醒）系统看不到，只能试
